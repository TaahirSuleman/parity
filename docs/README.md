# Docs map

What is in this folder, and what each document is for. Measured numbers come from one file, `eval/results/latest.md`; every other document quotes it.

| Document | What it is |
|---|---|
| `17-validation-results.md` | What was proven on the live Meta Model API, stage by stage, with run ids, costs and the eval method; the per-stage model sweep's reading; `variance.json` holds the run-to-run data it cites. |
| `18-decision-and-development-plan.md` | The product decisions: the user, the job and the hero moment; the architecture and why one agent with gated tools; the evaluation design; the external-page decisions; the problem statement (Push the Frontier, software) with both sides weighed; the video storyboard. |
| `19-design-spec.md` | The design: modules, the Verifier's six checks, model roles and efforts, the data model, the API and event stream, Live and Replay modes, the public-site guard, the deploy, the eval harness. |
| `21-submission-text.md` | The submission form's answers, with every number equal to the eval file. |
| `22-workbench-design.md` | The workbench: what each panel shows and why, and the accessibility of the workbench itself. |
| `24-voiceover-pass.md` | Parity's own workbench run through VoiceOver, what was heard, and what changed because of it. |
| `voice-recording.md` | The kit that recorded VoiceOver reading the store pages (the clips under the store's voice folder), aligned to the focus log. |
| `26-muse-code-review-plan.md` and `27-muse-code-findings.md` | Muse Code as the review-only session: how it was run, its 80 findings across nine prompts, and the decision on each. |
| `28-final-claims-ledger.md` | Every number and claim in the video, the README and the form, traced to its source, with the real-world figures tagged primary, vendor or derived. |
| `31-architecture.md` | The system and integration map, one Live run's sequence, the trust boundaries, the eval loop, and every Meta capability with its model, tier, effort, API feature and checking code. |
| `img/` | The architecture diagram the README shows. |

Findings are evidence, not a conformance claim; a human approves every fix.
